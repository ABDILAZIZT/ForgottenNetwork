# Trust, privacy and accessibility audit — 2026-10-06

> **Current behavior (2026-10-15):** The interface is English-only. Main-canvas uploads are private drafts, previewable only by their owner. Publishing artwork or an avatar makes the referenced upload public after ownership and placement checks. Legacy pending uploads follow this same owner publication flow; hidden or rejected media stays blocked. Reports, automatic holds, and moderator removal remain active. Classic remote uploads still require advance review. Earlier descriptions of mandatory review for every permanent-canvas upload or the language switch below are historical.

This is an implementation inventory, not a legal compliance certificate. Policies are rendered at `/community`, `/privacy`, `/terms`, `/cookies`, `/refunds`, and `/safety`. They must be reviewed against actual deployment settings before claiming compliance or inviting children to create identities.

## Moderation that exists

`server/contentSafety.js` validates public text fields on the trusted API boundary, including nested Classic entity/layer metadata and development-only legacy routes. Permanent identity, artwork text and chat also validate at storage entry points. Unicode normalization, Arabic diacritic/tatweel folding, zero-width removal and limited common substitutions catch selected English and Arabic terms. This blocklist is **not** comprehensive semantic moderation. Reports may quote offensive text privately without being rejected by the public-text filter.

Uploads are decoded and constrained by size, pixel count, format and animation limits. New permanent-canvas uploads and Classic PostgreSQL uploads are private from ordinary visitors and cannot be placed or publicly displayed until a configured moderator approves them. Existing assets are quarantined once on upgrade. Without a permanent `CANVAS_MODERATOR_IDS` identity or a Classic database moderator, new uploads remain pending. Rejection keeps media private. This human review gate is **not visual content moderation**: no image classifier or scan is configured. Moderators can miss prohibited content, and already published strokes or composite drawings remain unscanned. No artwork is sent to a new third party. Do not advertise automatic image moderation or guaranteed child safety. A visual classifier needs a selected provider, credentials, all-frame/composite scanning design, failure policy, privacy disclosure, evaluation and human escalation before activation.

Permanent reports cover artwork, chat, media and profiles. Three distinct authenticated reporters with open reports temporarily hide active artwork, approved media or chat while moderators review. If moderation brings the open distinct-reporter count below three, the system attempts to restore the temporary hold; artwork restoration still respects occupancy conflicts. This threshold can be abused and is not a finding that content violates a rule. Authenticated reporters can view their own outcomes. Configure `CANVAS_MODERATOR_IDS` with comma-separated immutable permanent artist UUIDs (never names or recovery secrets). The default is no moderator access. `/safety` exposes a review queue and pending upload previews to those identities only. Reviewers may approve/reject pending uploads, dismiss reports or hide artwork/chat/media; actions are audited. Profile reports require operator review and cannot currently be hidden from this UI. Classic PostgreSQL uses its separate database roles and moderator queue; three distinct authenticated open reports temporarily hide a contribution, and it is restored if review drops the count below the threshold. The two role systems are not interchangeable.

Artwork hiding uses tombstones and rebuilds only the creator's occupancy. Owners cannot restore moderator removals or automatic safety holds. Media responses use `no-store`; previously downloaded files and already cached older responses cannot be recalled. Connected clients receive refresh events. Retained original data supports investigation and recovery. A staffed moderation process and appeals contact remain operator responsibilities; no response deadline is promised.

## Deletion handling runbook / launch blockers

1. Assign trusted permanent moderator IDs and check the queue; do not expose recovery secrets in operational logs.
2. Requests bind to authenticated immutable identity IDs. Do not accept client-supplied alternate IDs as ownership proof.
3. Review permanent data plus associated Classic data (the bridge uses the same UUID), public attribution, uploaded media, reports, security records and backup coverage. Record a justified retention decision. Never blindly delete referenced rows or disable immutable-history triggers on production.
4. An automated erasure migration/processor and completion UI are **not implemented**. Operator-assisted processing requires a tested, backed-up procedure after retention/legal decisions. Until then, pending requests remain visible and must not be marked completed. Set a real operator contact and escalation procedure.
5. `render.yaml` uses a free web instance and does not declare a persistent SQLite disk. Verify actual `PERMANENT_DB_PATH`, durable volume and backup/restore configuration before relying on persistence across deploys. The health endpoint alone does not prove durable storage. No production DB command was run during this work.

## Asset provenance

No web font binaries are shipped; CSS font names fall back to locally installed/system fonts. This can change font metrics compared with previously downloaded Google fonts. Lucide's license is available in `client/node_modules/lucide-react/LICENSE`; preserve that notice when distributing its icons. Browser GIF decoding uses `gifuct-js` (MIT). Repository pixel sticker patterns are code-defined. `server/scripts/generate-brand-assets.js` contains the original geometric SVG source and Sharp generator for shipped app icons/social image, with no remote asset inputs. User media remain user submissions and are governed by the rules, not independently rights-verified. Do not treat a seed label as a third-party endorsement.
